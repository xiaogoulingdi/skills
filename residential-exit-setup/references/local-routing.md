# 自己维护本地分流规则

## 目的与边界

适用于用户希望自己决定哪些网站使用校园网直连、香港前置或家宽出口的情况。一次网站打不开不代表必须直连：先比较路径、错误、DNS 和目标地址；确认后才写规则。**当前线路和模式必须以运行状态为准**，不要沿用历史截图。

默认给用户可手动管理的少量规则；如用户要求自动国内分流，另行设计规则集、更新和验证。选择规则模式；全局模式通常忽略普通分流规则，以当前客户端实际行为为准。

## 界面操作

1. 打开 Clash Verge Rev 的「订阅」，找到要修改的配置；在未确认当前配置前不要切换订阅。
2. 右键配置，选择「编辑规则」。界面名称随版本可能有变化；找不到时查阅 [Clash Verge 自定义规则文档](https://www.clashverge.dev/guide/rules.html)，不要假设某个按钮已存在。
3. 在前置规则（Prepend）增加规则：规则类型、域名内容、策略分别填写；若支持文本编辑，使用下面 `类型,内容,策略` 的格式。策略组必须已经存在且名称完全一致。
4. 保存，确认实际运行模式为规则模式；重新加载可能短暂影响连接。查看 Clash 连接/日志，确认目标域名、匹配规则、策略链和最终出口；涉及登录服务时从业务入口重新发起登录，不重放包含凭据或一次性参数的 URL。
5. 失败时先撤销新规则或恢复变更前备份，并检查域名是否精确、较高规则是否先匹配、页面是否依赖其他域名、是否使用系统代理/TUN；不要仅凭网站能打开就断言匹配到了预期规则。

## 可修改的示例

以下域名是文档示例，并非用户真实网站。`香港前置选择` 和 `家宽出口` 必须替换成**当前配置中真实存在的策略组名称**，名称不匹配时不能生效：

```text
# 仅某个完整域名使用本地网络直连
DOMAIN,login.example.com,DIRECT

# 某个站点及其子域名使用香港前置节点，最终出口为香港
DOMAIN-SUFFIX,example.net,香港前置选择

# 某个站点及其子域名使用家宽出口，前提是该组已接入前置
DOMAIN-SUFFIX,example.org,家宽出口
```

如果界面分栏填写，以第一行为例：类型 `DOMAIN`，内容 `login.example.com`，策略 `DIRECT`；不要输入完整 URL、协议、路径、查询参数或登录凭据。`DOMAIN-SUFFIX,example.org` 通常包含根域名及其子域名；`DOMAIN` 仅匹配完整域名。谨慎使用范围宽的 `DOMAIN-KEYWORD`。

## 前置与后置，以及隐私含义

规则从上到下匹配，先命中先执行。前置规则通常位于订阅基础规则之前；后置规则在基础规则之后。若基础规则已经有 `MATCH` 兜底，放在其后的规则通常不会执行。多个前置规则也有顺序：先放精确例外，再放较宽的范围。

`DIRECT` 表示从当前本地网络访问，目标网站会看到本地网络出口；若网站走香港而非台湾，网站通常看到香港机场出口。分流也会影响 DNS 路径，不能笼统承诺 DNS 与页面出口一致。TUN 不保证所有应用、DNS、IPv6、WebRTC 都已经被成功接管。

## 规则存放与分享

- 本地配置原始 `rules`、订阅的远程规则、该配置的本地规则增强及全局增强是不同层；先检查实际配置和合并后的运行结果。官方文档说明订阅的「编辑规则」扩展通常不随订阅更新失效，但它并不自动写回或同步给朋友。
- 朋友想要同样规则：把经脱敏检查的规则明确加入可共享的配置，或让朋友自己添加；重新导入/更新后验证。不可把机场原始订阅链接、账号凭据或管理令牌当作公共规则发布。
- 如果用户选择导入开源规则集，要说明数据来源、许可证、更新机制、规则顺序、误判和失败时行为，并先在独立实例测试。单个例外应放在相关宽泛规则之前。
