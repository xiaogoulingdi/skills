# 香港前置—台湾家宽：脱敏故障与排查记录

这些案例来自一次真实搭建和后续排障；真实订阅地址、凭据、用户域名和 IP 均以 `xxx` 代替。下述结果是当时的观察，不保证以后相同；遇到新问题要重新测量，不要把相似症状直接当成同一根因。

## 1. 新导入配置后香港节点缺失或机场订阅加载失败

**观察**：测试配置默认流量走串联出口；机场节点 provider 尚未加载，节点列表不完整，测试脚本因找不到预期节点而报错。

**当时原因**：机场 provider 的下载请求可能被兜底规则送进尚未建立的串联链路；链路又依赖尚未下载的机场节点，形成启动循环。节点域名或解析器域名的启动解析也可能出现同类循环。

**检查与处理**：检查 provider 是否完成更新、节点筛选是否命中、更新请求走哪条策略；在验证可直连的网络环境下，显式为 provider 下载选择 `DIRECT`，并让启动解析走可用的解析路径。不能假定所有网络都能直连机场订阅，应先测可达性，必要时设计其他明确的启动路径。

**验收**：用运行时 provider 的更新时间和节点列表确认加载，等待节点就绪后再测试串联；记录下载路径与隐私影响，不把过滤器没命中归因于 DNS。

## 2. 独立测试失败，或看似成功但结果不可信

**观察**：曾有测试把上一次保存的响应当成本次结果；另一次临时核心的混合端口或 DNS 端口无法绑定，出现连接重置；后来当前订阅的 TUN/网络环境也影响了隔离链路。

**检查与处理**：每次测试独立生成结果，先确认进程启动、TCP 和 UDP 监听均成功、provider 已就绪，并检查进程退出码、连接错误与服务日志。临时端口要检查 TCP/UDP 冲突、Windows 保留端口与实际占用；不要只检查 TCP。

**边界**：Fake-IP DNS 立即返回虚拟地址，不证明上游能解析或目标网站能访问；同时测实际 HTTP(S) 和出口。隔离进程失败而当前用户的实际应用能用，不足以断言机场或 VPS 故障，应做旧配置对照、核对当前 TUN 与路径。

## 3. 多个节点、多个端口不等于已经自动切换

**观察**：可配置香港低延迟、故障切换与台湾备用端口；但当策略组手动选中某个香港节点或台湾端口时，当前使用的是固定选择。多端口还可能共用同一台 VPS 和同一个公网出口。

**检查与处理**：读取实际策略组 `now`，区分 `select`、`url-test` 和 `fallback`；检查健康探测目标、探测间隔、超时与 UDP 支持。按用户需要选择自动组或保留手选。

**验收**：在隔离配置中受控模拟主入口不可用，观察组选择改变，并用 DNS、HTTPS 和出口验证备用链路。一次隔离模拟成功不表示线上当前已处于自动模式，也不证明整台 VPS 故障能够切到另一台服务器。

## 4. 动态 IP 看似没有自动更新

**观察**：本地配置卡片的更新时间不变化，让人误以为所有内容都未更新。

**检查与处理**：分别核对：①机场 proxy-provider 节点刷新；②VPS 上的 DDNS 定时器、最近一次执行与 DNS A 记录；③本地配置文件和规则增强。三者更新时间与传播方式不同。使用域名后，记录 IP 更新与 DNS/客户端缓存的可能延迟；IPv6 硬编码地址不随 A 记录变化。

**验收边界**：曾验证 DDNS 服务按周期运行，并用过受控的过期记录修复测试；不能把这说成“实际 ISP 换 IP 已模拟成功”。NAT 机器还需证明出站 IP 与入站端口映射使用的公网 IP 一致。

## 5. 国内网站和机构登录超时

**观察**：串联配置只给少数域名写了直连例外，兜底 `MATCH` 走台湾，因此未被列出的国内网站也会走台湾出口。学校认证站点入口当时直连可返回 200，台湾串联访问超时。

**检查与处理**：对具体域名分别比较本地直连、香港和台湾路径，并查看运行时规则；如确定单站点直连可用，使用本地前置规则。Windows 系统代理绕过、Clash 规则和 TUN 接管是不同层；单独的 Windows 绕过项可能在 TUN 或代理开关变化时不适用。新规则放在能抢先匹配的规则与 `MATCH` 前。

**验收边界**：认证网站首页 HTTP 200 不代表机构登录完成、授权成功或有全文权限。IEEE 机构登录当时尚未验证完整流程；应确认用户选择的机构、跳转失败阶段、登录后返回和授权结果。程序得到 HTTP 418 也不能替代真实浏览器判断。切勿要求用户提供一次性 SAML 全链接或校园密码。

## 6. Threads 慢，X 却正常

**观察**：在一次同一香港前置的对照中，Threads 首页经台湾出口超时，直接走香港可打开；X 在两条路径均返回 200。

**检查与处理**：先验证两个目标各自的分流和实际路径，不因“X 正常”就断言台湾出口访问所有站点正常。若用户接受香港出口，可把相关域名设为香港前置；实际登录、媒体和相关资源可能使用其他域名，要根据连接记录逐个核对。

**边界**：单次结果不能确定是 IP 风控、路由或临时故障；只测首页不代表登录、图片、视频都已验证。全球模式和规则模式若选择的节点不同，不能只按模式名称比较。

## 7. DNS 检测显示香港，台湾出口 IP 正常

**观察**：配置客户端 Quad101 加密 DNS 后，Clash 的单次解析检查显示台湾；但浏览器检测网站仍看到香港 Cloudflare 和台湾 Google。关闭浏览器安全 DNS 后该现象仍存在。

**排查**：观察检测网站随机子域名的实际连接、规则和策略链；读取 VPS Xray 出站 DNS 与系统解析器。浏览器通过 HTTP 代理发送目标域名时，VPS 出站也可能解析；客户端查询成功不证明浏览器最终目标的所有解析都使用客户端 DNS。解析器的权威查询地址、服务节点、任播和地理数据库也可能不同。

**当时处理及验收**：先隔离测试，再为 VPS Xray 配置加密 DNS，逐服务部署并使用定时回滚。真实浏览器的两个检测站点之后均观察到台湾解析器；检测具有时间与范围限制，未看到校园网 DNS 不等于所有应用没有泄露。

## 8. VPS 加密 DNS 自举异常或个别域名无法解析

**观察**：某次台湾 VPS 的系统 DNS 对台湾加密 DNS 服务域名返回无效地址；使用解析器的已核验 IP、正确服务端名称和 TLS 证书验证可正常建立加密连接。只配置主解析器时，个别检测网站出现解析失败；加入第二个加密解析器后恢复访问。

**检查与处理**：隔离测试目标解析器是否可达、证书和服务端名称正确、启动域名如何解析及主备解析器失败行为。需要静态自举地址时确认服务商官方地址、更新策略和两端兼容性；不能关掉证书校验。逐服务应用前准备可独立执行的回滚，确保被重启服务不是唯一管理通道。

**边界**：备用解析器可能位于不同地区、采用不同过滤与隐私策略；可能引入额外延迟。要实测常用网站和备用路径，不因检测网站显示台湾就保证所有域名始终可访问或全部从台湾解析。

## 9. 本地订阅与好友使用的配置不一致

**观察**：用户自己添加的规则可能保存在本地增强中，机场 provider 自动刷新的是节点列表，不等于自动刷新本地完整配置，也不会自动把本地增强同步给朋友。

**检查与处理**：区分远程订阅、本地源配置、规则增强、运行时合并结果和共享订阅。交付时说明每项如何更新；需要共享规则时提供可共享的脱敏配置，或让朋友手动添加。不要共享管理令牌、原始机场订阅或 VPS 管理密码。
