# 典型任务：示例与验收

本文件是任务演练，不包含真实连接信息。`xxx`、虚构域名和端口均是占位符；不能直接复制到生产环境。

## 场景 A：新增一个家宽出口，保留原线路

**请求**：“我买了一个新的家宽 VPS，现有机场当前正在使用，新增一个节点先测，不要切换。”

**动作**：读取现有配置和当前策略组选择；核对新 VPS 的 SSH、IP 与 NAT 端口映射，备份目标服务；在独立端口运行新入口并用隔离客户端串联现有前置测试。生成独立候选配置并验证，不更改活动配置。需要更改 VPS 服务时使用独立管理路径或定时回滚。

**验收**：新端口握手、HTTPS、出口 IPv4/IPv6、浏览器 DNS 及延迟各有结果；现有活动配置与节点选择前后相同。DNS 检测未做则标明未验证；不要把候选文件生成当成新线路已上线。告知用户如何在合适时段导入或启用。

## 场景 B：网站在台湾出口超时，但香港可访问

**请求**：“一个网站在家宽出口打不开，能否只让它走香港，我以后自己加？”

**动作**：对具体域名分别测试当前家宽、香港前置和直连；确认当前配置的香港策略组名称和 `MATCH` 的位置。给用户具体的前置规则和本地界面操作，让其自行决定添加；用户直接授权代改时先备份、按授权应用并验证。

**规则样例**：`DOMAIN-SUFFIX,example.net,香港前置选择`；这是虚构域名及示例组名。登录与图片可能涉及其他域名，应查看实际连接再逐个处理。

**验收**：规则模式下查看实际目标域名、匹配规则与策略链；网站可用不等于命中规则。说明此站点的出口是香港，其他未匹配网站仍按原策略，且用户朋友不会自动获得本地增强规则。

## 场景 C：动态 NAT 的旧出口迁往新 VPS

**请求**：“把旧台湾家宽换到新机器，用户暂时继续上网。”

**动作**：新机器使用独立端口、凭据、临时域名与独立 DDNS；验证出站公网 IP 与入站映射关系、IPv4 与 IPv6、备用端口及主备 DNS；旧线路继续运行。切换正式 DNS 前先停旧 updater 并确认不会重启，保存原记录和 TTL，再完成切换并检查传播。

**验收**：从实际前置访问新出口，记录 IPv4/IPv6、DNS 检测与各端口结果；模拟 IP 变化或故障时明确测试方式及影响，做不到就标记未验证。若连接中断、更新冲突或结果异常，恢复旧记录/旧规则及服务并检查旧线路，保持备份。

## 场景 D：DNS 网站显示出口与解析器地区不一致

**请求**：“香港前置、台湾出口，但检测结果是香港 DNS，能否排查？”

**动作**：分别确认客户端普通 DNS、浏览器自行 DoH、实际被规则命中的代理链和服务端最终目标域名解析。读取服务端运行配置，不把本地 Whoami 测试当浏览器检测。新 DNS 先隔离测试，再备份、逐服务应用和浏览器复测；DNS 屏蔽或某个域名解析失败时测试备用及业务影响。

**验收**：记录每个检测网站实际看到的解析器与地区、出口、测试时间和浏览器设置；区分校园 DNS 暴露、公共解析器位置差异和未知原因。不能把“未看到校园 DNS”扩大为全设备绝无泄漏，也不能承诺固定地区或 AI 风控结果。
