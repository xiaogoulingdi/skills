# 家宽出口接入与迁移

目标：基于用户现有设备与线路，把新的住宅网络出口作为独立可测试的下游接入；按用户意图选择新增备用、迁移替换或只做诊断。不要把案例中的服务商、协议、节点、地址或端口当成新机器的默认值。

## 资料路由

- 每次实际操作前阅读 [接入与测试清单](references/checklist.md)。
- 更换服务器、域名或 DDNS 时阅读 [迁移与回滚](references/migration.md)。
- 需要复用本用户香港—台湾设计或解释其工作机制时阅读 [脱敏现有实例](references/current-hk-tw-example.md)。实例是历史参考，运行时状态和数据必须重新核实。
- 交付后需要用户自行添加或维护网站分流规则时，阅读并向用户讲解 [本地分流规则操作](references/local-routing.md)；按实际界面及策略组名称调整，不替用户默认启用一整套国内规则。
- 需要具体操作思路或判断验收边界时，阅读 [典型任务示例](references/scenarios.md)。
- 遇到节点不显示、网站超时、DNS 地区不一致、DDNS 或独立测试异常时，读取 [实际故障与排查记录](references/troubleshooting.md)；每条都是脱敏的历史案例，不等同于新问题的根因。

## 执行原则

1. **确认目标与约束。** 判断用户是新增出口还是替换旧出口，记录是否允许切换订阅、节点、重启服务和短暂断连；遵守当前会话中已有授权。可并行做只读检查和隔离测试，不无故打断现有链路。
2. **先采集实际状态。** 记录活动配置、节点及策略组选择、分流规则、TUN、客户端及服务端 DNS、供应商的公网/内网映射、可用 IPv4/IPv6、服务与防火墙。说明哪些是实测、哪些是推断；不要为读取证据暴露凭据。
3. **准备备份及回滚。** 修改前备份受影响的客户端配置、VPS 服务与配置、DNS 记录及权限，校验可读取和还原。新旧设备并行时保留旧线路；远端操作可能中断管理连接时，先设置独立的定时回滚或等效恢复手段，并验证触发条件；逐服务更改，完成验证后再解除保护。
4. **隔离搭建。** 对协议、证书、端口、NAT 和 DNS 按新机器实际条件选择；官方来源验证安装包，预先做配置语法检查。新出口使用独立的配置/端口/域名与凭据，不通过导入新配置偷偷切换当前订阅。临时目录与文件按最小权限保护。
5. **验证真实链路。** 对每个计划启用的出口验证前置连通、握手、最终公网 IPv4/IPv6、代理访问、代表性 HTTPS、DNS 以及重启后持久性；比较直连/前置/串联并记录样本与时间。自动切换需在隔离环境中模拟失效，手动指定节点或端口不等于自动切换。
6. **完成后报告。** 清楚列出配置变更、选择和保留的旧状态、测试条件及结果、未测试范围、回滚位置、后续手动操作。DNS 检测地区、住宅属性或 AI 可用性不保证恒定；未验证不能写成成功。
7. **交付可维护性。** 说明如何在用户当前客户端手动添加单站点前置规则、选择规则/全局模式、检查命中结果与恢复；告知本地规则和共享订阅的区别。若用户明确希望自行维护，保留其选择，不擅自导入大型规则集。

## 隐私与服务边界

- 不把机场订阅 URL、账户密码、API 令牌、UUID、私钥、真实域名或真实 IP 写入 skill、日志、报告、示例、PR 或截图；以 `xxx` 代替。需要实际信息时使用私有配置、交互式输入或受限凭据存储，避免命令行参数和日志泄露。公开的 DNS 服务 IP 不属于用户凭据，但新方案应重新验证。
- DNS 记录更新应最小权限，NAT 入站地址与出站探测结果必须独立验证；不要由两台机器同时更新同一记录。不要在未经验证的情况下清理旧服务、令牌或备份。
- 按来源官方文档核对当前版本的参数、兼容性与许可： [Mihomo DNS](https://wiki.metacubex.one/config/dns/)、[Xray DNS](https://xtls.github.io/config/dns/)、[Xray Sockopt](https://xtls.github.io/config/transports/sockopt/)。网络服务和产品行为可能变化。
